## Объяснение решения

в каждом списке первый оставшийся элемент это минимальный среди оставшихся в этом списке;

значит, меньший из двух первых элементов  минимальный среди всех еще не выбранных. добавляемр его и  сохраняем сортировку результата;
каждый раз передвигаемся дальше ровно в одном списке, поэтому каждый исходный узел попадет в ответ один раз

когда один список закончился, оставшаяся цепочка уже отсортирована и ее значения не меньше последнего выбранного, поэтому можно присоединить ее целиком

в способе 1
создаем фиктивный узел start перед результатом, поэтому даже первый узел добавляем обычным действием tail.next;
в конце возвращаем start.next, сам фиктивный узел в результат не входит.
в способе 2
фиктивного узла нет, поэтому сначала отдельно выбираем меньший из первых узлов это будет наш head;
дальше присоединяем остальные узлы так же, как в первом способе, и возвращаем head.

## Оценка сложности

пусть в первом списке n узлов, во втором m;

время в худшем случае O(n + m), тк  на каждом шаге выбираем один узел и двигаемся только вперед;
остаток списка присоединяем одной ссылкой, без обхода

дополнительная память O(1) и в первом и втором способе мы храним только несколько ссылок, а в первом способе еще один фиктивный узел;


## Визуализация

первый список: 1a -> 2a -> 4a;
второй: 1b -> 3b -> 4b;

a и b показывают, из какого списка взят узел.

способ 1:
создаем start, tail сначала указывает на него;
выбираем меньший из двух текущих узлов. при равенстве берем из первого списка;
выбранная часть растет так:
start -> 1a

start -> 1a -> 1b

start -> 1a -> 1b -> 2a

start -> 1a -> 1b -> 2a -> 3b

start -> 1a -> 1b -> 2a -> 3b -> 4a

первый список закончился, присоединяем 4b. возвращаем start.next.

способ 2:
сразу выбираем 1a как head, без start;
потом так же добавляем 1b, 2a, 3b, 4a и остаток 4b. возвращаем head;
оба способа дают 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> None.
