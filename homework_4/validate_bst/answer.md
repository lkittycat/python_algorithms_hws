## Объяснение решения

для каждого узла все значения в левом поддереве должны быть меньше его значения, а в правом больше. одинаковые значения не допускаем, как в первой задаче;

сравнивать узел только с его детьми недостаточно: потомок может нарушить ограничение от корня;

в стеке храним узел и две границы: lower и upper. значение должно быть строго между ними. None означает, что границы нет;

сначала кладем корень без границ. достаем узел через pop и проверяем его значение. если оно нарушает хотя бы одну границу, возвращаем False;

для левого ребенка верхняя граница становится значением текущего узла, а нижняя сохраняется. для правого ребенка меняется нижняя граница, а верхняя сохраняется;

так каждый узел проверяется с учетом ограничений от всех предков;

если стек закончился и нарушений нет, возвращаем True. пустое дерево тоже считаем корректным BST;

дерево не меняем. используем обычный список как стек, без рекурсии.

## Оценка сложности

пусть n - количество узлов, h - высота дерева;

время O(n) в худшем случае: каждый узел добавляем в стек и проверяем один раз;

дополнительная память O(h) для стека, не больше O(n). для сбалансированного дерева O(log n).

## Визуализация

корректное дерево:

```text
    4
   / \
  2   6
 / \ / \
1  3 5  7
```

для 2 верхняя граница 4, для 3 границы 2 и 4;

для 6 нижняя граница 4, для 5 границы 4 и 6;

все значения подходят под свои ограничения, результат True;

некорректное дерево:

```text
    5
   / \
  2   8
     / \
    4   9
```

4 меньше своего родителя 8, но находится в правом поддереве 5 и должна быть больше 5;

для этого узла lower = 5, upper = 8. значение 4 нарушает нижнюю границу, результат False;

повтор значения:

```text
  2
   \
    2
```

правый ребенок должен быть строго больше 2, результат False.
