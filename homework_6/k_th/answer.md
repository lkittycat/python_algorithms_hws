## Объяснение решения

используем quickselect. k считаем с 1, повторы учитываем отдельно: второй по величине элемент [5, 5, 3] равен 5;

k-ый по величине стоял бы на индексе target = n - k в отсортированном по возрастанию массиве. сам массив сортировать не нужно;

выбираем случайный опорный элемент в текущем участке и разбиваем участок на три части: меньше pivot, равные pivot, больше pivot;

во время разбиения поддерживаем границы:

```text
[left, lower)       < pivot
[lower, current)   = pivot
[current, upper]   еще не проверены
(upper, right]     > pivot
```

если текущий элемент меньше pivot, меняем его с nums[lower] и увеличиваем lower и current. если больше - переносим в конец непроверенной части и уменьшаем upper. current при этом оставляем на месте: пришедший справа элемент еще не проверен. если равен, увеличиваем только current;

когда current > upper, участок полностью разбит. индексы lower..upper заняты значением pivot, и в отсортированном массиве это значение занимало бы те же позиции;

если target левее lower, продолжаем только в левой части. если правее upper - только в правой. иначе ответ равен pivot;

нужная позиция всегда остается в рассматриваемом участке, на каждом шаге он уменьшается или сразу находим ответ. порядок внутри отброшенных частей нам не нужен;

разбиение на три части позволяет обработать все одинаковые значения за один проход. массив меняем на месте, полностью его не сортируем. при k вне диапазона 1..n, в том числе для пустого массива, выбрасываем ValueError. по условию k - целое число.

## Оценка сложности

пусть n - длина массива, сравнения и обмены занимают O(1);

ожидаемое время O(n) благодаря случайному выбору опорного: каждый проход линейный по длине текущего участка, а продолжаем только в одной части. в среднем размеры рассматриваемых участков убывают геометрически;

худшее время O(n²), если случайно каждый раз выбирается крайний по значению элемент и нужная часть уменьшается только на 1;

дополнительная память O(1): меняем исходный массив, храним только границы и опорное значение. рекурсии, копии массива и кучи нет;

для массива из одинаковых чисел время O(n), тк после первого разбиения target сразу попадает в блок равных.

## Визуализация

nums = [3, 2, 1, 5, 6, 4], k = 2, target = 6 - 2 = 4;

один возможный выбор случайных опорных: сначала 4, затем 5;

первый проход, pivot = 4:

| Действие | Массив | lower | current | upper |
| --- | --- | --- | --- | --- |
| начало | [3, 2, 1, 5, 6, 4] | 0 | 0 | 5 |
| 3 < 4 | [3, 2, 1, 5, 6, 4] | 1 | 1 | 5 |
| 2 < 4 | [3, 2, 1, 5, 6, 4] | 2 | 2 | 5 |
| 1 < 4 | [3, 2, 1, 5, 6, 4] | 3 | 3 | 5 |
| 5 > 4, обмен с последним | [3, 2, 1, 4, 6, 5] | 3 | 3 | 4 |
| 4 = 4 | [3, 2, 1, 4, 6, 5] | 3 | 4 | 4 |
| 6 > 4, обмен с собой | [3, 2, 1, 4, 6, 5] | 3 | 4 | 3 |

получили [3, 2, 1] < 4, [4] = 4, [6, 5] > 4. target = 4 правее блока равных, оставляем участок с индексами 4..5;

второй проход, pivot = 5:

```text
[3, 2, 1, 4, 6, 5]
              ^  ^
6 > 5: меняем 6 и 5, upper = 4
[3, 2, 1, 4, 5, 6]
              ^
5 = 5: current = 5, разбиение закончено
```

теперь lower = upper = target = 4, возвращаем nums[4] = 5. левая часть [3, 2, 1] осталась неотсортированной, но ответ уже найден.
