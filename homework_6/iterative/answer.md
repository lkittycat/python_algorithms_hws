## Объяснение решения

mergesort собирает отсортированные участки снизу вверх. сначала каждый отдельный элемент уже отсортирован, ширина участка width равна 1;

на каждом проходе сливаем соседние участки длины width в buffer. границы ограничиваем длиной массива, поэтому последний участок может быть короче или не иметь пары;

для каждого места в buffer берем меньший из первых оставшихся элементов двух участков. если один участок закончился, берем элементы другого;

после прохода меняем result и buffer местами и удваиваем width. перед каждым проходом все участки длины width отсортированы, а после слияния отсортированы участки длины 2 * width. когда width >= n, отсортирован весь массив;

quicksort хранит границы отложенных участков в списке stack. вместо рекурсивного вызова достаем пару границ через pop;

partition выбирает последний элемент опорным, переносит значения <= pivot в начало и ставит опорный на окончательную позицию. справа остаются значения > pivot;

большую часть кладем в стек, меньшую обрабатываем сразу во внутреннем цикле. участки длины 0 и 1 больше не разбиваем. каждый раз опорный занимает свое место, а остальные элементы попадают в одну из двух частей, поэтому после обработки всех участков массив отсортирован;

рекурсивных вызовов нет в обеих функциях. обе возвращают новый список и не меняют исходный.

## Оценка сложности

пусть n - длина массива, сравнения и обмены занимают O(1);

mergesort: O(n log n) времени во всех случаях. за проход обрабатываем n элементов, ширину удваиваем O(log n) раз;

дополнительная память O(n): копия массива и один буфер длины n. буфер используем повторно на всех проходах;

quicksort: в среднем O(n log n) времени для случайного порядка различных значений, в худшем O(n²). худший случай получается, например, на упорядоченных массивах или одинаковых числах: каждый раз исключаем только один опорный;

стек занимает O(log n) памяти. пока откладываем участки, сразу переходим в меньшую часть, которая не больше половины текущей. поэтому одновременно отложенных участков не больше O(log n). с учетом копии массива общая дополнительная память O(n);

пустой массив и один элемент обрабатываем за O(1).

## Визуализация

mergesort для [5, 2, 8, 1, 3]:

| width | Сливаемые участки | Результат прохода |
| --- | --- | --- |
| 1 | [5] + [2]; [8] + [1]; [3] + [] | [2, 5, 1, 8, 3] |
| 2 | [2, 5] + [1, 8]; [3] + [] | [1, 2, 5, 8, 3] |
| 4 | [1, 2, 5, 8] + [3] | [1, 2, 3, 5, 8] |

дальше width = 8 >= 5, завершаем. на последнем проходе берем 1, 2, 3, затем остаток 5, 8;

quicksort на том же массиве. границы включительно, вершина стека справа:

| Действие | Массив | Стек после действия |
| --- | --- | --- |
| начальное состояние | [5, 2, 8, 1, 3] | [(0, 4)] |
| достаем (0, 4), pivot = 3, позиция 2 | [2, 1, 3, 5, 8] | [(0, 1)] |
| сразу обрабатываем (3, 4), pivot = 8, позиция 4 | [2, 1, 3, 5, 8] | [(0, 1)] |
| достаем (0, 1), pivot = 1, позиция 0 | [1, 2, 3, 5, 8] | [] |

при равных размерах частей откладываем левую и сразу обрабатываем правую. оставшиеся участки из одного элемента не требуют разбиения, стек опустел.
