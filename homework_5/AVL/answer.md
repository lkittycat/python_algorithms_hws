## Объяснение решения

AVL - бинарное дерево поиска, в котором для каждого узла высоты левого и правого поддеревьев отличаются не больше чем на 1

как в прошлой домашке , узел хранит value, left, right. дополнительно сохраняем height: у пустого поддерева высота 0, у листа 1;

insert вставляет число, delete удаляет его, search возвращает найденный узел или None. вставка и удаление меняют дерево и возвращают None

повторы не добавляем, как в предыдущем BST. удаление отсутствующего значения ничего не меняет.

### Вставка и поиск

вставляем рекурсивно по правилу BST: меньшие значения идут влево, большие вправо

на обратном пути пересчитываем высоту и балансируем каждый узел. функция возвращает новый корень поддерева, поэтому после поворота обновляются и ссылки родителей, и self.root;

поиск идет от корня: если значение совпало, возвращаем узел; если искомое меньше, идем влево, иначе вправо. дошли до None - значения нет

### Балансировка

balance_factor = height(left) - height(right)

если он равен -1, 0 или 1, поворот не нужен

если больше 1, перевешивает левое поддерево. если левый ребенок перевешивает вправо, сначала поворачиваем его влево, затем текущий узел вправо. иначе достаточно одного правого поворота;

если меньше -1, действуем симметрично

поворот сохраняет порядок BST: промежуточное поддерево переносим между старым и новым корнем. высоту сначала обновляем у старого корня, затем у нового, потому что новый зависит от старого

после удаления баланс ребенка может быть 0. в таком случае тоже делаем одинарный поворот, поэтому в проверках двойного поворота используются строгие < 0 и > 0.

### Удаление

сначала находим узел по правилу BST;
если детей нет, возвращаем None. если ребенок один, возвращаем его вместо удаляемого узла

если детей два, находим минимальный узел в правом поддереве - следующий по порядку. копируем его значение в текущий узел и удаляем сам следующий узел из правого поддерева

так сохраняется порядок BST и удаляется ровно одно значение;

на обратном пути обновляем высоты и балансируем все затронутые поддеревья. при удалении повороты могут понадобиться на нескольких уровнях, поэтому не останавливаемся после первого

после каждой операции сохраняются оба свойства: правильный порядок BST и разница высот не больше 1 во всех узлах.

## Оценка сложности

пусть n - количество узлов;

высота AVL O(log n), поэтому поиск, вставка и удаление занимают O(log n) в худшем случае. поиск следующего узла при удалении тоже проходит не больше высоты дерева

обновление высоты и каждый поворот занимают O(1), так как высоты уже сохранены в узлах

поиск итеративный, его дополнительная память O(1). вставка и удаление рекурсивные, им нужно O(log n) памяти для стека;

все дерево занимает O(n) памяти. для пустого дерева операции занимают O(1).

## Визуализация

четыре случая вставки, значения добавляем в указанном порядке:

```text
LL: [3, 2, 1]          RR: [1, 2, 3]

    3                   1
   /                     \
  2                       2
 /                         \
1                           3

правый поворот у 3     левый поворот у 1

    2                       2
   / \                     / \
  1   3                   1   3

LR: [3, 1, 2]          RL: [1, 3, 2]

    3                   1
   /                     \
  1                       3
   \                     /
    2                   2

левый у 1,            правый у 3,
затем правый у 3      затем левый у 1

    2                       2
   / \                     / \
  1   3                   1   3
```

удаление листа с последующей балансировкой:

```text
до delete(5):     после удаления:     правый поворот у 4:

    4                 4                    2
   / \               /                    / \
  2   5             2                    1   4
 / \               / \                      /
1   3             1   3                    3
```

у 4 после удаления высоты 2 и 0, баланс 2. баланс ребенка 2 равен 0, достаточно правого поворота;

удаление корня с двумя детьми:

```text
до delete(4):          после:

      4                   5
     / \                 / \
    2   6               2   6
   / \ / \             / \   \
  1  3 5  7           1   3   7
```

минимум справа - 5. заменяем значение корня на 5, затем удаляем прежний узел 5. после пересчета высот дерево уже сбалансировано;

пример поиска 3 в итоговом дереве: 5 -> 2 -> 3. для поиска 4 путь 5 -> 2 -> 3 -> None, возвращаем None.
