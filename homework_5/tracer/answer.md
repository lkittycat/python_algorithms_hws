## Объяснение решения

tracer - декоратор для обычных синхронных рекурсивных функций. перед вызовом печатаем имя функции и аргументы, после вызова - результат;

счетчик depth хранится в замыкании. при входе увеличиваем его на 1, при выходе уменьшаем. один уровень соответствует четырем пробелам;

рекурсивный вызов тоже проходит через декоратор, поэтому по отступам видно, какие вызовы еще находятся в стеке;

аргументы передаем через *args и **kwargs, результат возвращаем без изменений. wraps сохраняет имя и описание исходной функции;

если функция выбросила исключение, печатаем его вместо результата и передаем дальше. depth уменьшаем в finally, поэтому после ошибки следующий вызов снова начинается без отступа;

каждая декорированная функция имеет свой счетчик глубины. здесь показываем прямую рекурсию одной функции; общий стек взаимной рекурсии разных функций не отслеживаем.

## Оценка сложности

пусть C - количество вызовов, h - максимальная глубина рекурсии, L - суммарная длина напечатанных строк;

управление счетчиком занимает O(1) на вызов. общие дополнительные затраты времени O(C + L), если построение repr линейно по длине представления;

длина строки зависит от глубины, аргументов и результата. поэтому сам вывод нельзя считать O(1) на вызов;

декоратор добавляет O(h) стековых кадров. еще в активных кадрах хранятся строки отступов и аргументов: их суммарный размер нужно учитывать отдельно. например, для аргументов постоянного размера на глубине h отступы могут занимать O(h^2) памяти;


## Визуализация

дерево вызовов factorial(3):

```text
factorial(3)
└── factorial(2)
    └── factorial(1)
        └── factorial(0) = 1
```

вывод программы:

```text
-> factorial(3)
    -> factorial(2)
        -> factorial(1)
            -> factorial(0)
            <- factorial = 1
        <- factorial = 1
    <- factorial = 2
<- factorial = 6
```

сначала доходим до базового случая n = 0. затем снимаем вызовы со стека в обратном порядке и получаем 1, 1, 2, 6.
