## Объяснение решения

идем по массиву слева направо. для текущего числа value нужно найти второе число k - value;

в словаре seen храним уже просмотренные числа и их индексы;

если нужное число есть в словаре, возвращаем его индекс и текущий i. первый индекс будет меньше, потому что число из словаря встретилось раньше;

если нет, записываем текущее число и его индекс в seen и идем дальше;

сначала проверяем пару, а только потом добавляем число в словарь. так не получится взять один и тот же элемент два раза, но два одинаковых числа с разными индексами использовать можно;


## Оценка сложности

пусть n — длина массива;

проходим его один раз, поиск и добавление в словарь занимают в среднем O(1), поэтому ожидаемое время O(n);

при большом числе коллизий словаря теоретически время может вырасти до O(n²);

дополнительная память O(n), потому что в словаре может оказаться до n разных чисел. 

## Визуализация

arr = [1, 3, 4, 10], k = 7;

сначала seen = {};

i = 0, число 1, нужно 6. его нет, сохраняем 1: 0;

i = 1, число 3, нужно 4. его нет, теперь seen = {1: 0, 3: 1};

i = 2, число 4, нужно 3. оно есть в seen, его индекс 1;

возвращаем (1, 2), потому что arr[1] + arr[2] = 3 + 4 = 7. до числа 10 уже не доходим.

пример с одинаковыми числами: arr = [5, 5, 1, 4], k = 10;

на индексе 0 нужна еще одна 5, но словарь пока пустой. сохраняем {5: 0};

на индексе 1 снова нужна 5, теперь она есть. возвращаем (0, 1), это два разных элемента.
