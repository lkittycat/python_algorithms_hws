## Объяснение решения


сама таблица - список ячеек, каждая ячейка - список, каждая пара - список [key, value]. 

capacity - количество ячеек, size - количество пар. изначально ячеек 8, но можно передать другое положительное целое число;

ячейки создаем отдельно в цикле, чтобы они не ссылались на один и тот же список;

номер ячейки получаем как hash(key) % capacity. используем встроенную функцию hash, но хранение, поиск, удаление и расширение реализуем сами. сторонних библиотек нет;

ключ должен поддерживать hash и не менять свой хеш и равенство, пока хранится в таблице. например, подходят числа и строки, а список ключом быть не может. он вызовет TypeError;

insert находит ячейку и перебирает пары. если ключ уже есть, заменяет значение, size не меняется. иначе добавляет новую пару;

search ищет ключ в его ячейке и возвращает значение. если ключа нет, вызывает KeyError. поэтому сохраненное значение None не путается с отсутствием ключа;

delete находит пару в ячейке, удаляет через pop и уменьшает size. если ключа нет, тоже вызывает KeyError.

## Коллизии и расширение

разные ключи могут попасть в одну ячейку, храним все такие пары в списке и сравниваем сами ключи, а не только их хеши;

например, при capacity = 4 числа 0, 4 и 8 попадают в ячейку 0;

перед добавлением новой пары проверяем, не станет ли количество пар больше 75% от количества ячеек. это коэффициент загрузки, а не доля непустых ячеек;

если станет, удваиваем capacity, создаем новые ячейки и распределяем туда все старые пары. просто скопировать ячейки нельзя, потому что остаток от деления на новую capacity может измениться;

size при переносе не меняется. после расширения добавляем новую пару;

при удалении таблицу не уменьшаем. если много ключей имеют одинаковые хеши, расширение не избавит от этой коллизии, но пары все равно сохранятся и будут доступны.



## Оценка сложности

пусть n - количество пар, c - количество ячеек;

при хорошем распределении хешей поиск и удаление занимают в среднем O(1). вставка - O(1) в среднем амортизированно, то есть с учетом редких расширений;

одно расширение занимает O(n + c): создаем новые ячейки и переносим пары. вставка, которая вызвала расширение, поэтому может быть линейной;

если все ключи попадут в одну ячейку, поиск, вставка и удаление могут занимать O(n). при удалении из списка еще нужно сдвинуть оставшиеся пары;

память O(n + c), включая ячейки и пары, без размера самих объектов ключей и значений. после многих удалений ячейки остаются, поэтому память не обязательно пропорциональна текущему n;

создание таблицы занимает O(c) времени и памяти. хеширование и сравнение ключей здесь считаем за O(1); для длинных строк нужно учитывать их длину.

## Визуализация

создаем HashTable(4), все ячейки пустые;

insert(0, "a"): ячейка 0 содержит [[0, "a"]], size = 1;

insert(4, "b"): тоже ячейка 0, теперь [[0, "a"], [4, "b"]], size = 2;

insert(8, "c"): в ячейке 0 уже три пары, size = 3;

search(4): перебираем ячейку 0, находим ключ 4 и возвращаем "b";

insert(4, "new"): меняем значение у ключа 4, size остается 3;

insert(1, "d"): четвертая пара превысит порог 3, поэтому сначала увеличиваем capacity до 8;

ключи 0 и 8 остаются в ячейке 0, ключ 4 переходит в ячейку 4. новую пару [1, "d"] кладем в ячейку 1, size = 4;

delete(0): в ячейке 0 остается [[8, "c"]], size = 3;

search(8) возвращает "c", а search(0) вызывает KeyError.
